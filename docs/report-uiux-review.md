# HTML 检查报告 UIUX 评估与优化方案（2026-08-27，v1 → v2）

评估对象：`test_paper_refcheck_20260827.html`（v1，Playwright 全页截图逐区块审查）

## 一、评估发现（按严重度排序）

| # | 问题 | 严重度 | 所属区块 |
|---|------|--------|----------|
| 1 | **无全局结论**：打开报告要先看 8 张卡片自己拼结论，"我能不能投稿"这个首要问题没有直接回答 | 高 | 顶部 |
| 2 | **无导航**：真实论文 60-150 条文献，报告很长，滚动后无法跳转/感知位置 | 高 | 全局 |
| 3 | **严重度无视觉分层**：§1 疑似编造（最致命）和 §4 重复条目（轻微）长得一模一样，全是白卡片 | 高 | 区块 |
| 4 | **链接不像可点击**：纯文字蓝色链接混在正文里，用户反馈的"方便复核"诉求打折扣 | 中 | 全局 |
| 5 | **元数据对照表无引导**："论文所写 vs 数据库记录"两列颜色相同，要自己分辨哪个是对的 | 中 | §2 |
| 6 | **附录表头不固定**：长列表往下滚就看不到列名；问题行和正常行无区分 | 中 | 附录 |
| 7 | **正文字号 13px 偏小**、行距紧，长报告阅读疲劳；标题与正文对比度不足 | 中 | 全局 |
| 8 | **卡片数值 0 也是大数字**：8 张卡片视觉权重相同，零值项制造噪音 | 低 | 汇总 |

## 二、v2 优化方案

| # | 改动 | 解决 |
|---|------|------|
| 1 | 顶部加**全局判定横幅**（红/黄/绿三档）："🚨 发现 1 条疑似不存在的文献——投稿前必须逐条人工确认" | #1 |
| 2 | **吸顶导航条**：锚点跳转 + 每项带计数徽章（非零着色、零值灰显），附录直达 | #2 |
| 3 | 区块和卡片加**严重度左边框**（红/黄/蓝）+ 严重区块淡色底 | #3 |
| 4 | 链接改为**药丸按钮**样式（DOI 蓝色实边、检索链接灰边），带 ↗ 外链提示 | #4 |
| 5 | 对照表：论文所写标红、数据库记录标绿加粗——"改这个"一眼可见 | #5 |
| 6 | 附录表头 sticky（随吸顶导航定位）；问题行整行淡色底 | #6 |
| 7 | 字号 13→14px，行距 1.7→1.75，区块标题 17→18px，留白加大 | #7 |
| 8 | 零值卡片数字缩小、灰色，非零严重项卡片着色底 | #8 |

## 三、保持不变

- 自包含单文件（内嵌 CSS，无外部依赖，可直接分享）
- `.item` / `.badge` class 契约（Claude 层 §6/§7 填充依赖）
- 报告文件名与自动 `open` 行为


## 四、v3 增量（design-taste 技能审计后，2026-08-28）

该技能判定本报告属"高密度信息文档"（非 landing page），仅适用其通用品味规则。落地的增量改动：

| 改动 | 依据 |
|------|------|
| 蓝紫渐变头图 → 平实深墨蓝 + 金色细顶线 | 渐变头图是 LLM 默认套路；学术工具要可信感不要炫 |
| 标题/区块标题/判定标题改衬线（Georgia + 宋体栈） | 学术出版语境下衬线正当，且立刻脱离"通用后台"感 |
| 统计数字与表格 `tabular-nums`、ID 列等宽字体 | 数字列对齐，长附录表可扫读 |
| 删 h1 装饰性 📚 emoji | 语义性 ✅❌⚠️ 保留（它们是状态不是装饰） |
| 链接 `:focus-visible` 焦点圈 | 键盘可达性 |
| 中文破折号停顿 → 冒号结构 | 去 AI 文风痕迹 |

保持的约束：自包含单文件、`.item`/`.badge` class 契约、浅色主题锁（打印型文档）。


## 五、v4 评估（ui-ux-pro-max skill 审计，2026-08-28）

用户四条反馈驱动的 v4 改版（删置顶横幅 / 空模块不渲染 / 配色降饱和 / 拍平嵌套卡片）落地后，用 ui-ux-pro-max 的规则库做了一次系统审计。

### 通过项（13/14 对比度实测过 AA）

| 检查项 | 实测 | 结论 |
|--------|------|------|
| WCAG 对比度 | 正文 14.63:1、muted 4.76:1、四个语义徽章 5.0–6.7:1、DOI 按钮白字 14.63:1 | 14 对中 13 对 ≥4.5:1 |
| 焦点可达 | `a:focus-visible` 焦点圈（v3 已加） | PASS |
| 行高/行长 | line-height 1.75，容器 max-width 1080px | PASS |
| 标题层级 | h1→h2→h3 无跳级 | PASS |
| 数字排版 | 统计数字/表格/ID 全部 tabular-nums | PASS |
| 视口 | viewport meta 完整，未禁用缩放 | PASS |
| 打印 | @media print 隐藏导航、区块防跨页断裂 | PASS |
| 语义冗余 | 状态不只靠颜色（✅❌⚠️ 图标 + 文字徽章并存） | PASS |

### 唯一 FAIL 与处置

- **零值计数/页脚浅灰 `#94a3b8` = 2.56:1** —— 刻意弱化的装饰性信息（零值本就该视觉消失，页脚是生成元数据）。判定为可接受的意图性降权，不改。

### 本轮修掉的三处（v4.1）

| 改动 | 依据规则 |
|------|----------|
| `scroll-behavior: smooth` 包进 `prefers-reduced-motion: no-preference` | reduced-motion |
| 最小字号 11.5px → 12px（徽章、导航计数） | readable-font-size |
| ≤640px：附录长表 `overflow-x: auto` 横滚兜底 + 收紧留白 | Table Handling (Responsive) |

### 记录性的取舍（不修）

- **emoji 做状态图标**（✅❌⚠️）：skill 规则推荐 SVG 图标库，但报告的硬约束是**自包含单文件、零外部依赖**，语义状态 emoji 是该约束下的正解。
- **导航无当前区高亮**（nav-state-active）：需要 JS 做 scroll-spy，报告刻意保持零 JS；锚点跳转 + 吸顶导航已满足定位需求。
- **复核链接钮 22px 高度 < 44pt 触控标准**：桌面打印型文档，鼠标为主要交互；移动端仅作浏览兜底。
