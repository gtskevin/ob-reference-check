# ob-reference-check — Skill 设计文档

> **状态：** 设计共识稿（2026-08-27，经三轮盘问达成）
> **用途：** 论文提交前，系统性检查所有参考文献，拦截 AI 编造文献、元数据错误、引用不当等问题。

---

## 1. 背景与目标

用户是组织行为学（OB）研究者，与合作者使用 AI 辅助写作。AI 可能编造不存在的文献，或引用不恰当（文献真实但不能支撑论述）。本 Skill 在**投稿前**做一次性全面体检，把论文中所有与参考文献相关的问题一次查出。

**核心设计原则：** 机械工作交给脚本（快、稳、零 LLM token），Claude 的 token 只花在机器做不了的判断上（引用恰当性、格式一致性）。

## 2. 检查范围（8 类）

| # | 检查项 | 执行者 | 说明 |
|---|--------|--------|------|
| 1 | 存在性验证 | 脚本 | 文献是否真实存在（OpenAlex 模糊匹配 + Crossref DOI 核对） |
| 2 | 元数据核对 | 脚本 | 作者/年份/期刊/卷期页/DOI 与真实记录逐项比对 |
| 3 | 引用恰当性 | Claude（分诊后） | 摘要 vs 正文论述比对，判断是否支撑 |
| 4 | 双向对应 | 脚本 | 正文引了但列表没有 ↔ 列表有但正文从未引用 |
| 5 | 重复条目 | 脚本 | 同一文献以略不同格式出现两次（AI 改写常见） |
| 6 | 格式一致性 | Claude | 同一 style 内部统一：et al. 规则、& vs and、年份括号等 |
| 7 | 时间线异常 | 脚本 | 引用了不可能存在的文献（成稿日期后出版、卷期页超前） |
| 8 | 版本问题 | 脚本 | preprint vs 正式发表版，DOI 是否一致 |

## 3. 架构

```
论文文件 (.docx / .pdf / .md)
        │
        ▼
┌─────────────────────────────┐
│  scripts/refcheck.py        │   Python，无外部工具依赖
│  ├─ parser     三格式解析     │   python-docx / PyMuPDF / 原生
│  ├─ extractor  引用提取       │   正文 (Author, Year) 标记 + 参考文献列表
│  ├─ verifier   存在性+元数据  │   OpenAlex 主 + Crossref 兜底
│  ├─ checks     8类检查        │   4/5/7/8 纯逻辑
│  ├─ cache      全局缓存       │   ~/.reference_check/cache/，按 DOI/标题哈希
│  └─ report     报告骨架生成   │   机械结果全部写入
└─────────────────────────────┘
        │  报告骨架（含待判断项）
        ▼
┌─────────────────────────────┐
│  Claude（SKILL.md 指挥）      │
│  ├─ A/B/C 分诊确认            │
│  ├─ A 类承重引用逐条深查       │   摘要 vs 论述比对
│  ├─ B 类轻查（真实+主题相关）   │
│  ├─ 格式一致性审查（第 6 类）   │
│  └─ 报告定稿渲染              │
└─────────────────────────────┘
        │
        ▼
  <论文文件名>_refcheck_YYYYMMDD.html （论文同目录，自包含 HTML，浏览器直接打开）
```

## 4. 关键决策记录

| 决策点 | 结论 |
|--------|------|
| 输入格式 | Word / PDF / Markdown，Python 库直读，不依赖 pandoc |
| 引用 style | 不限于 APA，覆盖 OB 常用 style（解析器按通用模式 + style 参数） |
| 数据源 | OpenAlex 为主（模糊检索）+ Crossref 兜底（DOI 核对）；不用 Google Scholar |
| API key | 免费无 key 可用；`OPENALEX_API_KEY` / `CROSSREF_API_KEY` 环境变量可选加速；**绝不硬编码** |
| 报告形式 | Markdown，浏览器打开；每条结果带 `[DOI]`（出版商页）+ `[OpenAlex]`（免费元数据+摘要）可点击复核链接 |
| 报告语言 | 中文（引用保留英文）；v2 可加 `--lang en` |
| 缓存 | 全局 `~/.reference_check/cache/`，存 API 原始返回，改稿重查秒命中 |
| Skill 名 | `ob-reference-check`（待确认拼写，见 §8） |
| 安装位置 | 本项目开发 → 完成后装到 `~/.claude/skills/ob-reference-check/` |
| 分发 | GitHub 公开 repo；不用 Claude Code 的人可手动跑脚本完成 1/2/4/5/7/8 类检查 |

## 5. 恰当性检查的分诊策略（第 3 类）

| 类别 | 判定 | 检查深度 |
|------|------|----------|
| **A · 承重引用** | 支撑假设、理论推导、关键论断 | 逐条深查：摘要 vs 正文句子比对，判断是否真的支撑 |
| **B · 顺带提及** | 背景介绍类引用 | 轻查：确认真实 + 主题相关 |
| **C · 引用堆砌** | 括号内并排 ≥3 条 | 只查真伪（层 1+2），跳过恰当性 |

分诊由脚本初筛（句子位置 + 引用密度）+ Claude 确认。报告会显示每处分诊结果，用户可手动调整类别后重查。预计 token 消耗约为全量深查的 1/3。

## 6. 报告模板（样例）

```markdown
# 参考文献检查报告 — <论文名>
检查日期：2026-08-27 ｜ 引用总数：98 ｜ 文献列表：102 条

## 汇总
| 状态 | 数量 |
|------|------|
| ✅ 确认无误 | 71 |
| ❌ 疑似不存在 | 3 |
| ⚠️ 元数据不一致 | 9 |
| ⚠️ 恰当性存疑（A类深查） | 6 |
| 🔗 对应关系问题 | 5 |
| ❓ 无法验证 | 4 |
| 📝 格式一致性 | 8 处 |

## ❌ 疑似不存在（3 条）—— 最优先处理
### [R12] Bakker, Demerouti, & Xie (2019). Leadership and JD-R...
- 论文写法：*Journal of Applied Psychology, 114(3), 345–367*
- 数据库检索：OpenAlex / Crossref 均无匹配记录（标题相似度最高 0.42）
- 🔍 复核：[OpenAlex 搜索](...) ｜ 建议：检查是否为 AI 生成，需人工确认

## ⚠️ 元数据不一致（9 条）
### [R23] 年份不一致
| 字段 | 论文所写 | 数据库记录 |
|------|----------|-----------|
| 年份 | 2017 | **2016** |
| 页码 | 345–367 | 332–356 |
- 🔍 复核：[DOI](https://doi.org/10.1037/xxx) ｜ [OpenAlex](https://openalex.org/W123)

## ⚠️ 恰当性存疑（A 类深查）
### 引用处 [§3.2 H2]："X 显著提升 Y（Smith, 2020）"
- 文献摘要要点：Smith (2020) 研究的是 **X 对 Z** 的影响，未涉及 Y
- 判断：摘要中找不到对 Y 的论述支撑
- 🔍 复核：[DOI](...) ｜ 建议：换引或补充直接证据
```

## 7. 实施步骤

1. **M1 · 解析与提取**：三格式 parser + 正文引用标记/参考文献列表提取（纯脚本，先拿一篇真实论文验证提取准确率）
2. **M2 · 验证与缓存**：OpenAlex/Crossref 查询 + 全局缓存 + 元数据逐项比对
3. **M3 · 机械检查**：双向对应、重复条目、时间线异常、版本问题 + 报告骨架生成
4. **M4 · Claude 层**：SKILL.md 编写、A/B/C 分诊流程、深查/轻查/格式审查的 prompt 设计
5. **M5 · 端到端测试**：用一篇真实论文（含已知的 AI 引用错误）完整跑一遍，验证报告可用性
6. **M6 · 交付**：安装到 `~/.claude/skills/`，建 GitHub repo，写 README（含无 Claude Code 用户的手动用法）

每个里程碑结束跑真实论文回归，防止解析回归。

> 📖 **为什么 OpenAlex 比直接搜 Google Scholar 更可靠？**
> Google Scholar 没有官方 API，程序访问会被反爬拦截，结果不稳定。OpenAlex 是开放的学术数据库（索引 2.5 亿+ 作品），提供免费 API 且支持标题模糊匹配——特别适合"拿着一条可能被 AI 写错了的引用去找真实文献"这个场景。
