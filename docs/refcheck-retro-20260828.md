### 层 2：定稿机制（本次交付 bug 的直接来源，架构级）

**P0-1：废除「Claude 手改 HTML」模式。** 本次 emoji bug 的本质是：定稿要求把「概览卡片 + nav 计数 + 各节状态 + 附录 82 行徽章」五处保持一致，靠人肉 regex 同步必然漏。改为：

```
refcheck.py <论文>              # 初筛，生成底稿 + JSON（现状）
Claude 复核 → 写 <论文>_final.json
                                # 结构：{ id, final_status, verdict, evidence, action }[]
refcheck.py --finalize <论文>    # 读 final.json，按模板重渲染最终 HTML
```

徽章、计数、附录、概览全部由模板数据驱动，「漏改某一处」这类错误结构性消失。skill 第 6 步从「替换 todo」改为「产出 final.json」。

### 总评

- **AI-native 智能：✅** — 判断与机械的分工方向正确（这正是本次 17 项误报被拦下的原因）；问题不在分工而在**边界渗漏**：两边各有少量对方的活（F1：⚙️ 活漏给了 🧠；F2：🧠 判断漏给了 ⚙️）。
- **AI-native 交互：✅** — 目标导向、单次交付、证据可溯，符合用户「只要结论」的偏好。
- 两维不合并打分；交互层无需改造，智能层的问题已全部映射进第三节优化方案（F1=P0-1/P2-2，F2 强化 C2 的修法，F3 为新增项）。
- 漂移敏感点：未来给脚本「加容差规则」最易退化（每加一条静默规则 = 从 AI 层收回一类判断）——F2 的 tolerance-suppressed 机制是长期护栏。
