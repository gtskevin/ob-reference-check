# ob-reference-check 检查覆盖清单

> 用途：GitHub README 的"具体查什么"表格素材。面向用户（OB 及相关领域学者），说明每类检查**拦的是什么风险**，而不只是技术描述。
>
> 依据：SKILL.md 工作流程 + `refcheck.py` 各 check 函数实际逻辑（2026-08-28 核对）。

## 一张总表：8 类检查

| # | 检查类别 | 具体查什么 | 帮你拦住什么 |
|---|---------|-----------|-------------|
| 1 | **存在性核实** | 每条文献在 OpenAlex / Crossref / Semantic Scholar 三源交叉检索；无 DOI 且三源未命中时 Crossref DOI 直查兜底；自动未命中的条目由 AI 二次复核（查出版商页、精确标题）后才允许下结论 | **AI 编造的假文献**——作者、年份、期刊、页码全都像真的，唯独论文不存在；这是导致拒稿/解聘的最高风险项 |
| 2 | **元数据逐项比对** | 作者、年份、期刊名、卷、期、页码、DOI 逐字段与数据库记录比对；词级容差区分真实笔误 vs online-first / 页码简写 / DOI 迁移；期刊名拼写（Review vs Reviews） | 页码写错（709–712 vs 709–734）、期刊名拼错、年份不符——审稿人一眼能看出的问题 |
| 3 | **正文—列表双向对应** | 正向：正文引用了、但参考文献列表里没有（报告渲染为专属卡片，附引用句原文和补录建议）；反向：列表里有、正文从未引用 | 补写段落时随手引了一篇、忘了加进列表——投稿前最常见、审稿人一眼就能看到的疏漏 |
| 4 | **重复条目** | 同一文献在列表中重复出现 | 复制粘贴段落时带进来的重复 |
| 5 | **时间线与预印本** | 出版年份晚于当前年份（不可能存在的文献）；引用的是 preprint（arXiv / PsyArXiv / SSRN 等）而正式版可能已发表 | AI 幻觉常"发明"未来年份；preprint 引用可能被要求更新为正式版 |
| 6 | **列表内交叉检测** | 两条文献的 DOI 互换错挂；同作者多条是否按年份升序、同年是否缺 a/b 后缀；标题开头残留章节编号 | DOI 错挂会把你引向别人的论文；排序错误是格式审查的常见扣分点 |
| 7 | **引用恰当性** | 按引用角色分诊：假设/推导句中的承重引用逐条深查（摘要是否支撑论述、结论方向是否一致、构念是否对齐）；背景性提及轻查主题相关；堆砌引用跳过 | **真文献但不支撑你的论点**——论文说正相关、文献其实是负相关，这和假文献一样致命 |
| 8 | **格式一致性** | et al. 使用规则、`&` vs `and`、年份括号、卷期斜体、页码范围符号（- vs –）、期刊缩写与全称是否混用；只报告内部不一致，不强推特定 style | 你的论文未必是 APA——查的是"自相矛盾"，不是"不合我的规范" |

## 谁做哪部分（分工）

| 层 | 覆盖 | 特点 |
|----|------|------|
| 脚本（机械层） | 第 1–6 类的全部检索、比对、匹配 | 零 token、免费、可复现；结果有本地缓存 |
| AI（判断层） | 第 1 类的二次复核分诊、第 7 类恰当性、第 8 类格式审查 | 只做机器做不了的判断；每条结论强制"结论 + 证据 + 修改建议"三要素 |

## 最终报告怎么呈现

| 卡片 | 含义 |
|------|------|
| 🔴 必须修改 | 确认的问题：假文献 / 元数据错误 / 正文引用缺失等，附证据和具体改法 |
| ⚠️ 存疑核对 | AI 不替你拍板、建议人工读原文的条目 |
| 🔵 格式调整 | 列表内部不一致 |
| ✅ 其余确认 | 其余条目已核验无误，折叠收纳 |

> 📖 **为什么"自动未命中"不等于"假文献"？**
> 检索可能因解析偏差、数据库收录延迟（近 3 个月新文献）、在线发表版本而未命中。所以脚本只报"未匹配"，AI 复核后仍找不到才标"无法核实"——报告永远不会替你断言"这条是编造的"，但也绝不会静默放过。
